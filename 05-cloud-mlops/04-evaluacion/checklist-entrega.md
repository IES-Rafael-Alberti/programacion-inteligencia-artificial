# Checklist de entrega — UD5 Cloud y MLOps

Usa esta lista antes de entregar. El profesorado indica cuál de las prácticas es evaluable en cada momento.

## Imprescindible (todas las prácticas)

- [ ] El fichero entregado coincide con la práctica indicada.
- [ ] El trabajo es propio y se declara el uso de IA si se ha utilizado.
- [ ] No se entregan claves API, tokens, contraseñas, credenciales ni ficheros `.env` reales.
- [ ] Se incluyen instrucciones o contexto suficiente para revisar el trabajo.

---


## Tarea comparativa de herramientas cloud

**Enunciado:** `03-practicas/tarea-comparativa-herramientas.md`
**Rúbrica:** `03-practicas/rubrica-tarea.md`

### Entregable individual (70 % de la nota)

- [ ] Se investigan al menos 2 alternativas para la categoría asignada, con datos comparables.
- [ ] La descripción del proyecto del grupo aparece al inicio del documento individual.
- [ ] Cada alternativa incluye: nombre, características clave, ventajas, limitaciones y caso de uso.
- [ ] Se justifica qué herramienta encajaría mejor para el proyecto del grupo y por qué.
- [ ] El documento está bien estructurado y usa terminología técnica correcta.

### Entregable grupal (30 % de la nota)

- [ ] El documento grupal consolida las aportaciones de todos los miembros.
- [ ] Se cubre cada categoría de herramienta (Feature Store, Compute, MLOps, Frameworks, APIs LLM, Orquestación, Datos, Almacenamiento).
- [ ] La propuesta final indica qué stack se adoptaría para el proyecto y por qué.
- [ ] El reparto de trabajo por categoría está documentado o es evidente en el contenido.

## Tarea AWS

**Enunciado:** `03-practicas/01-AWS-Tarea_01.pdf`
**Esqueleto de código:** `03-practicas/esqueletoAWS.py`

- [ ] El script Python sigue la estructura del esqueleto proporcionado.
- [ ] Se completan las secciones marcadas como `TODO` o incompletas.
- [ ] El código no contiene credenciales reales (usar variables de entorno o placeholders).
- [ ] El fichero `scriptAWS.sh` se revisa y se adapta si el enunciado lo requiere.
- [ ] Se documenta brevemente qué hace cada paso del pipeline implementado.

## Comprobaciones finales

- [ ] He revisado la rúbrica o criterios de la práctica antes de entregar.
- [ ] El código ejecuta sin errores críticos en el entorno indicado.
- [ ] Las rutas de archivos son relativas o están documentadas.
- [ ] Los errores conocidos o limitaciones están documentados brevemente.

## Formato de entrega

- Según las instrucciones del profesorado: carpeta comprimida, repositorio o plataforma indicada.
- Incluir solo los archivos necesarios para revisar el trabajo.
- Usar nombres de archivo claros que identifiquen la práctica y el autor o grupo.
