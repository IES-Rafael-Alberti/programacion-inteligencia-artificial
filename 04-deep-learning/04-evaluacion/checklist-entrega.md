# Checklist de entrega — UD4 Deep Learning

Usa esta lista antes de entregar. Cada laboratorio tiene su propia plantilla de entrega en su carpeta; este checklist cubre lo común a todos y lo específico de cada uno.

## Imprescindible (todos los labs)

- [ ] El archivo de entrega está completo (informe, notebook o script según el lab).
- [ ] El trabajo es propio y se declara el uso de IA si se ha utilizado.
- [ ] No se entregan claves, tokens ni datos sensibles.
- [ ] Se indica cómo reproducir o revisar el trabajo.

## Lab 1 — TensorFlow Playground

- [ ] El informe incluye capturas de pantalla representativas de los experimentos realizados.
- [ ] Se documenta qué parámetros se variaron y por qué.
- [ ] Se interpretan los resultados: convergencia, sobreajuste y frontera de decisión.
- [ ] Se conectan las observaciones con conceptos teóricos (gradiente, activaciones, profundidad).
- [ ] El informe sigue la plantilla `TensorFlowPlayGround_Entrega.md`.

## Lab 2 — Backpropagation desde cero

- [ ] Se analiza el código fuente proporcionado (no solo se ejecuta).
- [ ] Se identifica y explica cada fase del algoritmo: forward, pérdida, backward, actualización.
- [ ] Se relaciona cada fragmento de código con el concepto teórico correspondiente.
- [ ] Se incluye un análisis crítico sobre limitaciones o diferencias con frameworks modernos.
- [ ] El informe sigue la plantilla `EstudioImplementacionBackpropagation-Entrega.md`.

## Lab 3 — De Playground a código real

- [ ] El notebook o script implementa un modelo con un framework real (Keras, PyTorch u otro).
- [ ] El modelo entrena sin errores críticos y produce resultados verificables.
- [ ] Se visualizan la curva de pérdida y la frontera de decisión (o equivalente para el problema).
- [ ] Se comparan al menos dos configuraciones (capas, activaciones u otro hiperparámetro).
- [ ] Se conectan los resultados con backpropagation y conceptos del taller.
- [ ] El código es limpio, comentado y reproducible.
- [ ] El informe sigue la plantilla `DePlayground_a_CodigoReal-Entrega.md`.

## Comprobaciones finales

- [ ] He revisado la rúbrica (`rubrica.md` o la específica del lab) antes de entregar.
- [ ] Las rutas de archivos son relativas o están documentadas.
- [ ] El trabajo puede revisarse sin acceder a recursos externos no indicados.
- [ ] Los errores conocidos o limitaciones encontradas están documentados.
